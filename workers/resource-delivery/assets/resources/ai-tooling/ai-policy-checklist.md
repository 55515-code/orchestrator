# Secure AI Adoption Policy Checklist

**Version:** 1.0 · **Category:** AI Tooling · **License:** Free

The #1 emerging risk for small businesses is unmanaged AI adoption — "shadow
AI." This checklist builds a lightweight, enforceable AI usage policy in an
afternoon.

## 1. Inventory What Is Actually Being Used

- [ ] Ask staff which AI tools they use for work (anonymized survey works best)
- [ ] Find browser extensions and SaaS AI features enabled by default
- [ ] Identify which tools touch customer, employee, or regulated data

## 2. Define Allowed / Restricted Use

- [ ] Publish a short classification: which data classes may NEVER be pasted
      into public AI tools (PHI, PCI, personal info, trade secrets)
- [ ] Approve a small allowlist of tools with data-protection terms
      (enterprise contracts, EU/US hosting, no-training opt-outs)
- [ ] State clearly that personal accounts are not for company data

## 3. Assign Accountability

- [ ] Name an AI owner (even part-time) who maintains the allowlist
- [ ] Set the review cadence (quarterly is a good start)
- [ ] Define who approves new AI tool requests and how (one-paragraph process)

## 4. Set Human-Review Requirements

- [ ] Any AI output that affects customers, contracts, or compliance decisions
      must be reviewed by a human before use
- [ ] AI-written code requires human review before production deployment
- [ ] AI-generated security/compliance documents are drafts until validated
      (see the quality-gate pattern in the prompt engineering guide)

## 5. Handling Shadow AI (without a ban)

- [ ] Recognize the demand: bans fail. Offer approved alternatives that cover
      the top 3 needs staff actually have
- [ ] Ask staff to request approval instead of silently adopting tools
- [ ] Log remediation, not blame, when shadow AI is found

## 6. Model and Prompt Hygiene

- [ ] Instruct staff to treat prompts as data (prompts can leak secrets)
- [ ] Disable chat-history/training sharing where the tool allows it
- [ ] Use redaction/tokenization for any unavoidable sensitive input

## 7. Keep It Current

- [ ] Re-check the allowlist quarterly (tools change terms without notice)
- [ ] Add AI tools to your vendor-risk review process
- [ ] Include AI use in security awareness training
